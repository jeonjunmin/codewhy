# 버그 리포트 — 쿠폰·VAT 적용 순서 오류

- **이슈:** #62
- **심각도:** P1 (회계 정합성 / 세금 과소 계산)
- **관련:** #60(부가세 정책), #61(통합 정산), #59(쿠폰)
- **보고자:** QA

## 1. 현상
`settlement_total()` 이 **쿠폰 할인 후 금액**에 VAT를 부과한다.
부가세 정책서 2항은 **할인 전 공급가**를 과세 기준으로 규정하므로, 세금이 과소 계산된다.

## 2. 재현 절차
```python
order = Order(amount=10000)          # 국내, 수수료 0
settlement_total(order, coupon_rate=0.2)   # 쿠폰 20%
```

## 3. 기대 vs 실제
| 항목 | 기대값 | 실제(버그) |
|---|---|---|
| 공급가 | 10,000 | 10,000 |
| VAT 과세 기준 | 10,000 (할인 전) | 8,000 (할인 후) |
| VAT | 1,000 | 800 |
| 최종 정산액 | 9,000 | 8,800 |

→ 주문당 **200원 세금 과소**. 거래량 누적 시 회계 불일치.

## 4. 원인
통합 정산 함수가 절차적으로 `apply_coupon` → `vat` 순서로 호출.
정책상 `vat` 는 할인 전 금액을 받아야 한다.

## 5. 수정 방향
- VAT를 `apply_coupon` **이전** 공급가 기준으로 계산하도록 순서 교정.
- 단기 핫픽스는 #62에서, 재발 방지를 위한 단계 분리는 #63(파이프라인)에서 처리.

## 6. 회귀 테스트
- [ ] 쿠폰 0% → 정산액 변동 없음
- [ ] 해외결제(수수료 3%) + 쿠폰 동시 적용
- [ ] 전액 환불 건 → 과세 기준 0
