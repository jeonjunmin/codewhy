## #58 — [시연용] 결제 금액 음수 입력 방어

**라벨:** `bug` `payment` **담당:** @yejin-kb

### 배경
환불 연동 과정에서 음수 `amount` 가 정산 모듈로 흘러들어오는 사례가 보고됐습니다.
음수 금액이 `final_charge()` 에 들어가면 청구액이 뒤집혀(마이너스 청구) 회계 정합성이 깨집니다.

### 요구사항
- 정산 진입점에서 `order.amount < 0` 이면 즉시 거부한다.
- 거부 시 명확한 에러(`ValueError`)를 던져 상위 결제 흐름이 잡을 수 있게 한다.

### 완료 조건
- [ ] `_assert_valid(order)` 추가, `final_charge()` 진입 시 호출
- [ ] 음수 금액 입력 시 `ValueError("주문 금액은 음수가 될 수 없습니다")`
- [ ] 정상 금액은 기존과 동일하게 동작

### 연관
- 코드: `demo/checkout.py` → `_assert_valid`, `final_charge`
- 이후 통합 정산(#61)의 사전 검증 단계로 재사용됨

## #59 — [시연용] 정산 시 쿠폰 할인 적용

**라벨:** `feature` `payment` `marketing` **담당:** @yejin-kb

### 배경
마케팅팀에서 프로모션 쿠폰을 도입합니다. 정산 단계에서 쿠폰 할인율을 반영해야 합니다.
정책 세부 사항은 첨부 기획서를 따릅니다.

📎 **첨부:** `쿠폰_할인_기획서.md`

### 요구사항
- 할인율(`coupon_rate`, 0.0~1.0)을 받아 금액에 적용하는 `apply_coupon(amount, coupon_rate)` 추가
- 할인 후 금액은 원 단위 반올림
- 쿠폰 미적용(`coupon_rate=0.0`) 시 금액 변동 없음

### 완료 조건
- [ ] `apply_coupon()` 구현
- [ ] 반올림 정책은 기획서 4항 준수
- [ ] VAT(#60)·통합 정산(#61)과의 적용 순서는 별도 이슈에서 확정

### 연관
- 코드: `demo/checkout.py` → `apply_coupon`
- 적용 순서 관련 후속 버그: #62

## #62 — [시연용] 쿠폰·VAT 적용 순서 버그

**라벨:** `bug` `payment` `finance` **우선순위:** `P1` **담당:** @yejin-kb

### 요약
`settlement_total()` 이 **쿠폰 할인 후 금액**에 VAT를 매겨, 세금이 과소 계산됩니다.
부가세 정책(#60, 정책서 2항)은 **할인 전 공급가**를 과세 기준으로 규정합니다.

📎 **첨부:** `버그리포트_쿠폰VAT_순서오류.md`

### 재현
- 주문 10,000원, 쿠폰 20%, 해외결제 아님
- VAT 기준: 공급가 10,000원 → 정상 VAT 1,000원
- **실제(버그):** 할인 후 8,000원 기준 → VAT 800원 (200원 과소)

### 기대 / 실제
| | 기대 | 실제(버그) |
|---|---|---|
| VAT 과세 기준 | 할인 전 10,000 | 할인 후 8,000 |
| VAT | 1,000 | 800 |

### 완료 조건
- [ ] VAT는 `apply_coupon` 이전의 공급가 기준으로 계산
- [ ] 회귀 케이스(쿠폰 0%, 해외결제) 동작 동일

### 연관
- 원인 정책: #60 / 통합 함수: #61
- 코드: `demo/checkout.py` → `settlement_total`

절차적으로 뭉쳐 있어 **단계별 검증·표시가 불가능**하기 때문입니다.

- 영수증/정산서용 `settlement_breakdown()` 으로 단계별 내역(dict) 제공
