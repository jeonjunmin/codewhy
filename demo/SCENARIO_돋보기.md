# 돋보기 시연 시나리오 — "커밋 메시지는 거짓말, 코드는 진실"

> **한 줄 컨셉:** 개발자가 해외 결제 수수료를 몰래 도입해놓고 커밋 메시지엔 "띄어쓰기 수정"이라 적었다.
> `git blame`은 그 거짓말을 그대로 보여주지만, **CodeWhy 돋보기는 실제 diff를 읽어 진짜 변경을 알려준다.**

이 시나리오는 돋보기의 가장 강력한 특징 — **커밋 메시지를 맹신하지 않고 실제 코드 변경(diff)을 근거로 설명한다** — 을 정면으로 보여줍니다.

---

## 0. 준비된 데이터 (이미 demo/magnifier 브랜치에 커밋됨)

분석 대상 파일: [`demo/checkout.py`](checkout.py) — 결제 수수료 계산 모듈.

| 순서 | 날짜 | 메시지 | 실제로 바뀐 것 | 이슈 |
|---|---|---|---|---|
| ① | 03-02 | `feat: 결제 수수료 계산 모듈 추가` | 파일 생성, 수수료율 **0%** | — |
| ② | 03-15 | `#57 결제 완료 화면 안내 문구 띄어쓰기 수정` ⚠️**거짓말** | `calculate_fee` 에 **해외 결제 3% 수수료 도입** (`0.0` → `0.03 if order.is_overseas`) | #57 |
| ③ | 03-28 | `#58 결제 금액 음수 입력 방어 코드 추가` | `_assert_valid()` 추가 (음수 주문 거부) | #58 |
| ④ | 04-09 | `feat: 정산 시 쿠폰 할인 적용 (#59)` | `apply_coupon()` 추가 | #59 |
| ⑤ | 04-24 | `feat: 부가가치세(VAT) 10% 합산 (#60)` | `VAT_RATE`, `vat()` 추가 | #60 |
| ⑥ | 05-12 | `#61 정산 총액 계산 함수 추가` | `settlement_total()` 로 수수료+쿠폰+VAT 통합 | #61 |
| ⑦ | 06-05 | `#62 쿠폰·VAT 적용 순서 버그 수정` | VAT를 **할인 전 공급가 기준**으로 교정 | #62 |
| ⑧ | 06-20 | `refactor: 정산 로직을 단계별 파이프라인으로 전면 재작성 (#63)` | `_steps()` 제너레이터 파이프라인 + `settlement_breakdown()` 으로 **전면 재구성** | #63 |

> ①②번은 **돋보기**, ①~⑧ 전체 흐름은 **타임라인**, 각 줄에 박힌 `#이슈번호`는 **요구사항 찾기** 시연을 받쳐줍니다.
> ③번 이후 커밋은 모두 23번 줄 아래에만 코드를 추가/수정하므로, **돋보기 주인공(23번 줄)의 blame은 그대로 ②번(#57)**으로 유지됩니다.

→ **23번째 줄** `return round(order.amount * (0.03 if order.is_overseas else 0.0))` 이 돋보기 시연의 주인공입니다.
이 줄을 `git blame` 하면 ②번 커밋(`#57 ... 띄어쓰기 수정`)이 잡힙니다 — **메시지만 보면 그냥 오타 수정처럼 보입니다.**

## 2. 시연 대본 (약 2분)

### ① 거짓말을 먼저 보여준다 (git blame의 한계)

> **멘트:** "이 줄, 해외 결제에 3% 수수료를 매기는 코드입니다. 누가 왜 넣었을까요?
> 기존 도구로 먼저 확인해 보겠습니다."

`화면` 23번째 줄 위에서 **마우스 호버 → GitLens/blame 표시** (또는 `git blame`)
→ **"#57 결제 완료 화면 안내 문구 띄어쓰기 수정"** 이 뜬다.

> **멘트:** "'띄어쓰기 수정'이라고 적혀 있네요. 그런데 이게 정말 띄어쓰기였을까요?
> **커밋 메시지는 사람이 손으로 적는 거라, 틀리거나 거짓일 수 있습니다.**
> 이 말을 그대로 믿으면 '아 사소한 수정이구나' 하고 그냥 넘어갑니다 — 그게 함정입니다."

### ② 돋보기로 진실을 꺼낸다

`화면` 23번째 줄 선택 → **우클릭 → `CodeWhy: 이 코드, 왜 바꿨어?`**

사이드바에 나타나는 것:

- **🔍 변경 사유 (콜아웃):** 커밋 메시지가 아니라 **실제 diff + 연관 이슈 #57**를 근거로,
  "이 줄은 해외 결제 시 **3% 수수료를 적용**하도록 바꾼 코드입니다" 류의 설명이 스트리밍으로 타이핑됨.
- **📎 출처:** Issue #57 배지
- **🕑 라인 수정 이력:** ②번 항목의 타이틀이 원본 메시지("띄어쓰기 수정")가 아니라
  **실제 변경 기준으로 교정**되어 "결제 수수료 계산 로직 변경" 같은 제목으로 바뀐다.

> **멘트:** "보세요. **커밋 메시지엔 '띄어쓰기 수정'이라고 적혀 있었지만**, CodeWhy는 그 말을 믿지 않았습니다.
> 실제 코드 변경(diff)을 직접 읽어서 — **`calculate_fee` 함수에 해외 결제 3% 수수료가 새로 생긴 것**임을 짚어냅니다.
> 게다가 연결된 기획 이슈(#57)까지 찾아, **'왜' 3%가 됐는지**까지 설명합니다.
> 즉, **거짓말하는 커밋 메시지 앞에서도 진실을 알려주는 도구**입니다."

## 2-B. 타임라인 시연 (약 1분)

> **멘트:** "이 파일이 어떻게 여기까지 왔는지, 커밋 8개를 직접 읽지 않고 한눈에 보겠습니다."

`화면` `demo/checkout.py` 에디터 **우클릭 → `CodeWhy: 이 파일의 역사 요약`**

사이드바에 나타나는 것:

- **한 문단 요약:** "이 파일은 3월에 수수료 0%로 시작해, 해외 결제 수수료·입력 검증·쿠폰·부가세가 차례로 붙었고,
  6월에 정산 로직이 **단계별 파이프라인으로 한 번 전면 재작성**됐습니다" 류의 흐름 요약.
- **주요 마일스톤:** 8개 커밋이 ①생성 → ②수수료 → ③검증 → ④쿠폰 → ⑤VAT → ⑥통합 → ⑦버그픽스 → ⑧재작성 으로 정렬.

> **포인트:** ⑦ `#62 적용 순서 버그 수정`과 ⑧ `#63 전면 재작성`은 **"한 번 엎어진 순간"**을 만들어,
> 타임라인이 단순 나열이 아니라 *변화의 굴곡*을 짚어낸다는 걸 보여줍니다.

## 2-C. 이슈(요구사항 찾기) 시연 (약 1분)

> **멘트:** "이 정산 코드가 결국 **어떤 기획 요구사항들에서 나왔는지** 거꾸로 따라가 보겠습니다."

`화면` 정산 관련 줄(예: `settlement_total` 또는 `vat`) 선택 → **우클릭 → `CodeWhy: 요구사항 찾기`**

사이드바에 나타나는 것:

- **연관 이슈 목록:** 한 파일에서 #57·#58·#59·#60·#61·#62·#63 가 모여, 키워드/열림·닫힘 상태로 필터.
- **이슈 상세:** 담당자·개설/업데이트 시점 + **연관 커밋·댓글·첨부 문서**가 활동 타임라인으로.
- **AI 질문:** "쿠폰과 VAT 중 뭐가 먼저 적용돼?" → 이슈 본문·#62 버그픽스 커밋을 근거로 답변.

> **포인트:** 돋보기가 "이 한 줄, 왜?"라면, 요구사항 찾기는 "이 코드 전체가 **어떤 기획들의 산물인지**"를 역추적합니다.
> 한 파일에 7개 이슈가 엮여 있어, 목록→상세→AI요약 흐름을 끊김 없이 시연할 수 있습니다.

## 3. 이 시연이 증명하는 것 (심사위원 어필)

- **돋보기는 커밋 메시지를 신뢰하지 않는다.** `git blame`이 그대로 보여주는 거짓 메시지와 달리,
  실제 `git show -p` diff와 +/-줄 수, 바뀐 함수명(`changedSymbols = calculate_fee`)을 근거로 삼는다.
- **두 군데에서 동시에 거짓을 바로잡는다:**
  1. 라인 수정 이력 **타이틀 교정** — 순수 git 데이터만으로 작동 (백엔드만 있으면 됨, GitHub 불필요)
  2. 콜아웃 **변경 사유 설명** — diff + 연관 이슈(#57)로 진짜 의도까지 복원
- **"주석/메시지가 거짓말하는 경우가 정보가 없는 것보다 위험하다"** (발표 슬라이드 2의 메시지)를 라이브로 입증.
